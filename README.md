# Сайт компании САНС

Корпоративный сайт САНС (Пермь) — упаковочные материалы и складское оборудование.

На выходе это обычный статический сайт: HTML, CSS и один JS-файл. Базы данных нет. PHP нужен только админке (`/admin/`) — посетители получают готовые HTML-страницы.

## Как устроено

Страницы **не редактируются вручную** — они собираются из данных и шаблонов. Иначе телефон или пункт меню пришлось бы править в 25 файлах.

```
data/products.json     товары, характеристики, варианты для корзины
data/site.json         телефон, почта, адрес, меню, год и дата обновления
content/*.html         текст главной, «О компании» и «Контактов»
includes/build.php     шаблоны (шапка, подвал, корзина, поп-ап, карточки) и сборка
scripts/build.php      запуск сборки с компьютера
admin/                 панель управления для заказчика
css/styles.css         оформление
js/script.js           меню, корзина, поп-ап скидки
```

Собираемые файлы — `index.html`, `pages/*.html`, `pages/products/*.html`.
Править их напрямую бессмысленно: следующая сборка перезапишет.

## Команды

Нужен PHP 7.4 или новее (проверить: `php -v`). Внешних библиотек нет. Сборщик на PHP, а не на Node, потому что его же вызывает админка на хостинге, где Node обычно нет. Короткие имена `npm run build`, `npm run check`, `npm run serve` по-прежнему работают и вызывают команды ниже.

Собрать сайт после изменений:

```bash
php scripts/build.php
```

Посмотреть локально вместе с админкой — сайт на http://localhost:3000, админка на http://localhost:3000/admin/:

```bash
php -S localhost:3000
```

Проверить, что собранные страницы соответствуют данным (полезно перед публикацией):

```bash
php scripts/build.php --check
```

## Как изменить содержимое

**Товар или его описание** — через админку (см. ниже) или вручную в `data/products.json`, затем `php scripts/build.php`.

Поля товара: `title` (заголовок страницы), `cardTitle` и `shortDescription` (карточка в каталоге), `description` (описание на странице), `specs` (характеристики), `features` (преимущества), `variants` (позиции с кнопкой «В корзину»), `related` (похожие товары — указываются по `slug`).

Поля `sku`, `price`, `unit` зарезервированы под будущий прайс: пока они `null`, на страницы ничего не выводится.

**Телефон, почта, адрес, пункты меню** — `data/site.json`. Меняются один раз, попадают во все 25 страниц.

**Тексты главной, «О компании», «Контактов»** — `content/*.html`. Внутри можно использовать подстановки `{{phone}}`, `{{email}}`, `{{address}}`, `{{productCount}}`; `{{root}}` — это путь к корню сайта, его подставляет сборщик.

**Фотографии** — папка `images/products/`, в JSON указывается путь вида `images/products/имя.jpg`.

## Адрес сайта и SEO

Сборщик сам делает: `robots.txt`, `sitemap.xml`, `canonical`, теги Open Graph и Twitter (превью ссылки в мессенджерах) и микроразметку Schema.org — `Product` и «хлебные крошки» на страницах товаров, `LocalBusiness` на главной и контактах.

Для части из этого нужен полный адрес сайта. Пока поле `url` в `data/site.json` пустое, сборка предупреждает об этом и пропускает `canonical`, `og:url`, `og:image` и `sitemap.xml` — чтобы не появились ссылки на несуществующий адрес.

Как только домен известен:

```json
"url": "https://ваш-домен.ру"
```

затем `php scripts/build.php` — карта сайта и остальные теги появятся сами. Адрес пишется без слэша в конце.

## Персональные данные

Страница политики конфиденциальности — `content/privacy.html`, реквизиты юрлица подставляются из `data/site.json` (`legalName`, `ogrn`, `inn`, `kpp`, `legalAddress`). У всех форм есть обязательная галочка согласия со ссылкой на политику: без неё форма не отправляется.

Если подключите счётчик посещений, добавьте его в `data/site.json`:

```json
"analytics": ["Яндекс.Метрика"]
```

Текст политики про сбор обезличенных данных появится сам. Пока список пуст, там написано, что счётчики не установлены.

## Приём заявок

Все три формы (контакты, поп-ап скидки, заявка из корзины) отправляют данные через один модуль в `js/script.js`. Адрес получателя задаётся один раз в `data/site.json`:

```json
"formEndpoint": "https://formspree.io/f/xxxxxxx"
```

Туда уходит POST с JSON: тип формы, имя, телефон, почта, комментарий, адрес страницы, а для заказа из корзины — ещё список товаров с количеством.

Подойдёт любой сервис, принимающий POST с JSON, — Formspree, Getform, FormCarry или свой обработчик. Главное, чтобы он разрешал запросы с домена сайта (CORS).

Пока поле пустое, формы не делают вид, что заявка ушла: показывают сообщение с просьбой позвонить, а сборка предупреждает об этом. Корзина очищается только после успешной отправки — если сервер недоступен, заказ и заполненные поля остаются на месте.

## Админка

Адрес — `/admin/`. Вход по паролю, логина нет. Что умеет:

- **товары** — название, подписи в каталоге, описание, характеристики, преимущества, ссылка «Заказать на сайте», фото, похожие товары, варианты с кнопкой «В корзину»; добавить, удалить, поменять порядок в каталоге;
- **контакты** — три телефона, почта, адрес. Ссылки `tel:` составляются из номера сами.

После каждого сохранения админка правит `data/*.json` и пересобирает страницы тем же `includes/build.php`. Перед записью сохраняется копия данных в `data/backups/` (хранятся последние 20). Фото проверяются по содержимому, уменьшаются до 1000 px и сохраняются в JPEG. Если старое фото больше нигде не используется, оно удаляется.

Защита: хранится только хеш пароля, после 5 неверных попыток вход с этого адреса блокируется на 15 минут, у каждой формы есть CSRF-токен, админку нельзя встроить в чужую страницу.

**Сменить пароль:** откройте `/admin/?newhash=НОВЫЙ_ПАРОЛЬ` и вставьте полученную строку в `SANS_ADMIN_HASH` в `admin/config.php`.

**Требования к хостингу:** PHP 7.4+ с расширением GD (для уменьшения фото; без него фото сохраняются как есть). PHP должен иметь право записи в `data/`, `images/products/`, `pages/`, а также в `index.html`, `robots.txt` и `sitemap.xml` в корне. Статический хостинг вроде GitHub Pages для админки не подходит.

Служебные заметки по прошлым доработкам — в `docs/history/`.
